Drawer Menu Versioning (Compose)

How to add a new WebSocket version to the Jetpack Compose drawer

1. Purpose of This Document

This guide explains how new feature versions (V1, V2, V3, etc.) are added to the application drawer when the drawer is implemented using Jetpack Compose.

In this project, the drawer is not driven by menu XML. It is fully controlled by a composable function.

2. Important Architecture Note

  • Drawer items are defined in a composable
  • Menu XML files are NOT used for WebSocket items
  • Each drawer item is manually wired to navigation
If a version is not added to the drawer composable, it will never appear in the UI—even if navigation is configured.

3. Drawer Source File

All drawer chat items are defined in: 

com.example.compose.jetchat.components.JetchatDrawerContent

4. Existing Pattern (V1 & V2)

Existing WebSocket versions are added using the following pattern: 

ChatItem("ws-chatV1", selectedMenu == "ws_chat_v1") {
    onChatClicked("ws_chat_v1")
}

ChatItem("ws-chatV2", selectedMenu == "ws_chat_v2") {
    onChatClicked("ws_chat_v2")
}

5. Adding a New Version (V3)

To add a new version to the drawer, insert a new ChatItem following the same pattern: 

ChatItem("ws-chatV3", selectedMenu == "ws_chat_v3") {
    onChatClicked("ws_chat_v3")
}
The string passed to onChatClicked() must exactly match the navigation key used in the activity.

6. How Navigation Is Triggered

Drawer clicks are routed in NavActivity using a when condition: 

"ws_chat_v3" -> findNavController().navigate(R.id.nav_ws_chat_v3)

As long as the keys match, navigation works automatically.

7. Best Practices

  • Keep version names consistent across UI and navigation
  • Add new versions below older ones for clarity
  • Never reuse an existing key for a new version
  • Treat newer versions as experimental unless promoted
