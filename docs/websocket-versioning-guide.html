WebSocket UI Versioning Guide

How to safely copy V2 to V3 and continue feature development

1. Purpose of This Document

This document explains the standard process used in this project to create a new WebSocket UI version (V3) from an existing version (V2).

The goal is to:

  • Preserve older versions for reference and rollback
  • Allow safe experimentation in newer versions
  • Maintain clean and readable project structure

2. Existing Folder Structure

All WebSocket UI versions are stored under the same module path: 

app/src/main/java/com/example/compose/jetchat/ui/websocket/
 ├── v1/
 ├── v2/
 └── v3/   (to be created)

Each version contains its own UI and Fragment implementation.

3. Creating V3 from V2

Step 1: Copy the V2 Folder

  • Right-click on v2 folder
  • Select Copy
  • Paste it inside the same websocket directory
  • Rename the pasted folder to v3

Step 2: Rename Files

Inside v3, rename the files using Android Studio refactor:

ConversationScreenV2.kt  →  ConversationScreenV3.kt
WebSocketChatV2Fragment.kt → WebSocketChatV3Fragment.kt
Always use Refactor → Rename to avoid broken references.

4. Updating Class and Function Names

Conversation Screen

@Composable
fun ConversationScreenV3(...) { }

Fragment Class

class WebSocketChatV3Fragment : Fragment() { }

Ensure all internal references are updated from V2 to V3.

5. Navigation Configuration

Add a new fragment entry for V3 in the navigation graph: 

<fragment
    android:id="@+id/webSocketChatV3Fragment"
    android:name="com.example.compose.jetchat.ui.websocket.v3.WebSocketChatV3Fragment"
    android:label="WebSocket Chat V3" />
Do not remove V2 navigation entries. Older versions must remain intact.

6. How V3 Should Be Developed Further

V3 is intended for improvements and experimentation without affecting V2.

Recommended Enhancements

  • Improved UI spacing and colors
  • Message animations
  • Typing indicators
  • Connection state display
  • Error and reconnect handling

Any V3-specific logic should remain inside the v3 package.

7. Best Practices

  • Never modify older versions after creating a new one
  • Keep ViewModels common, UIs versioned
  • Commit each version upgrade separately
  • Use V3 as a playground for new ideas
